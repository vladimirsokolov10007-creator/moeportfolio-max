# МоёПортфолио — мини-приложение для MAX

Мини-приложение для мессенджера MAX: централизованное хранение грамот, сертификатов,
дипломов и других свидетельств об участии в конкурсах и мероприятиях.

**Опубликовано:** https://vladimirsokolov10007-creator.github.io/moeportfolio-max/

## Назначение решения

Единое портфолио достижений школьника/студента: добавление наград с фото и описанием,
поиск, просмотр, формирование единого PDF и автоматическое резюме из достижений.
Все данные хранятся на устройстве пользователя — без регистрации, серверов и ключей.

## Основной пользовательский сценарий

1. Пользователь открывает мини-приложение в MAX (по ссылке `https://max.ru/<бот>?startapp`).
2. Нажимает «+», заполняет форму: фото документа, название, категория, организация, дата, описание.
3. Сохраняет — документ появляется в списке и открывается карточка с деталями.
4. Может поделиться: единый PDF со всеми наградами передаётся в нативное меню «Поделиться»
   (отправка в чат MAX или сохранение на устройство).
5. Может сформировать резюме из достижений (офлайн-генератор по шаблонам) и выгрузить его в PDF.

## Состав и архитектура

| Файл | Назначение |
|---|---|
| `index.html` | Само мини-приложение (единый файл: HTML + CSS + JS, офлайн-логика) |
| `server.js` | Минимальный статический HTTP-сервер для локального предпросмотра (`npm run dev`) |

Архитектура — одностраничное статическое приложение без бэкенда:

```
MAX клиент → WebView → index.html (вся логика на клиенте)
                │
                ├─ MAX Bridge (https://st.max.ru/js/max-web-app.js):
                │    профиль, кнопка «Назад», haptic, shareMaxContent
                └─ Хранение: WebApp.DeviceStorage (MAX) ⇄ localStorage (fallback),
                   с объединением и ре-синхронизацией при запуске
```

## Запуск через Docker (одна команда)

```bash
docker compose up --build
```

Приложение будет доступно по адресу http://localhost:7100/

Сборка занимает секунды: базовый образ `node:20-alpine`, внешних зависимостей нет.

## Параметры и переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `HOST` | `0.0.0.0` в контейнере / `localhost` локально | Адрес, который слушает сервер |
| `PORT` | `7100` | Порт HTTP-сервера |

Также поддерживаются аргументы командной строки `--host` / `--port` (приоритет выше переменных).
Токены, пароли и API-ключи не требуются. Пример см. в `.env.example`.

## Порты

- `7100` — единственный порт: отдаёт `index.html` и статические файлы.

## Зависимости

- Node.js ≥ 18 (только встроенные модули: `http`, `fs`, `path` — внешних npm-пакетов нет).
- Браузер для просмотра (локально) или клиент MAX (основной сценарий).

## Внешние сервисы и интеграции

- **MAX Bridge** — `https://st.max.ru/js/max-web-app.js` (официальный CDN MAX): профиль
  пользователя, системная кнопка «Назад», тактильные отклики, шеринг `shareMaxContent`,
  `DeviceStorage`. Без этой библиотеки приложение продолжает работать в браузере
  с fallback на localStorage.
- **GitHub Pages** — опциональный хостинг статической версии (автодеплой из `main`
  через `.github/workflows/pages.yml`). На работу приложения не влияет.

Других внешних сервисов нет; работа MVP ничего внешнего не требует.

## Работа с данными

- Документы хранятся на устройстве пользователя в JSON под ключом `moeportfolio_docs_v1`:
  сначала в `WebApp.DeviceStorage` (MAX), дублируются в `localStorage`.
- При каждом запуске обе копии читаются, объединяются по id (приоритет — более полная
  и более новая запись) и ре-синхронизируются — устойчиво к очистке одного из хранилищ.
- Фото документов сжимаются на клиенте (максимум 1024px, JPEG 0.75) и хранятся внутри JSON.
- Ни одно действие не отправляет данные на сервер: всё остаётся на устройстве.

## Тестовые данные

Специальные тестовые данные не нужны — сценарий проверяется созданием записей через UI.
Для воспроизводимой проверки достаточно добавить 2–3 документа через форму «+».

## Пошаговый сценарий проверки

1. `docker compose up --build` → открыть http://localhost:7100/ (или открыть приложение в MAX).
2. Нажать «+», заполнить: название «Диплом победителя», категория «Диплом»,
   организация, дата, описание; при желании — фото. Нажать «Сохранить».
3. Убедиться: открылась карточка документа, на главном экране счётчик «1 документ».
4. Нажать «← Назад» в карточке — возврат на главный экран, документ в списке.
5. Полностью закрыть и заново открыть приложение — документ на месте (проверка хранилища).
6. Нажать «📤 Поделиться» → «PDF со всеми наградами» — PDF формируется и передаётся
   в системное меню (в MAX: отправка в чат или сохранение; в браузере: скачивание).
7. Открыть «Резюме из достижений», сгенерировать — текст резюме и кнопка «📄 Скачать PDF».

## Ожидаемое поведение

- Каждое сохранение сразу отражается в списке и счётчике.
- Данные переживают перезапуск приложения и устройства.
- Поиск фильтрует список по названию, организации и описанию.
- PDF содержит титульный лист и по странице на каждый документ.

## Известные ограничения

- Данные привязаны к устройству (DeviceStorage/localStorage), перенос между устройствами
  возможен только через PDF/резюме или публичную карточку.
- Автоматическое сохранение PDF в папку Downloads внутри MAX не поддерживается платформой
  (скачивание через href заблокировано MAX) — используется нативное меню «Поделиться».
- Квота хранилища устройства ограничивает количество фото; при переполнении
  приложение показывает предупреждение.
- Лимиты DeviceStorage зависят от клиента MAX и не контролируются приложением.

## Остановка и повторный запуск

```bash
docker compose down      # остановка
docker compose up        # повторный запуск (пересборка не требуется)
```
